# 对话频率限制插件

`astrbot_plugin_rate_limiter` v1.6.1

滑动窗口限制私聊/群聊对话次数：任意 `window_minutes` 分钟内超限即拦截，不再调用 LLM。
支持白名单豁免、按用户/群单独设限、真实解锁倒计时、@机器人 才提示、静默唤醒直接拦截。

---

## 功能一览

| 功能 | 说明 |
|------|------|
| 私聊限制 | 每个 QQ 号每小时最多对话 N 次（默认 10） |
| 群聊限制 | 每个群每小时最多对话 N 次，**整群共享额度**（默认 30） |
| 计入范围 | @机器人、引用机器人消息、唤醒前缀 —— 一切能唤起 LLM 的群消息都计数 |
| 滑动时间窗口 | 窗口长度可自定义（默认 60 分钟），最旧记录滑出即恢复一条额度 |
| 真实解锁倒计时 | 超限提示里的等待时间 = 最旧记录滑出的真实时刻，不虚报 |
| @机器人 才提示 | 超限后只有 @机器人 和私聊会收到提示，不在群里刷屏 |
| 静默唤醒拦截 | 引用/前缀唤醒的消息超限后静默拦截，LLM 完全收不到，不消耗 token |
| 额度用尽提醒 | 额度内最后一条放行时单独发一条消息告知额度用完与最早可继续时间 |
| 超限静默期 | 提示发出后 N 秒内（默认 60）不重复提示，防连发刷屏 |
| 用户白名单 | 指定 QQ 号 → 不受任何限制 |
| 群聊白名单 | 指定群号 → 不受任何限制 |
| 单独用户限制 | 总开关 + 默认条数 + 按用户覆盖，指定 QQ 号用独立额度 |
| 群聊单独限制 | 指定群号 → 用独立额度，不用全局默认 |
| 配置即时生效 | 所有配置每次请求实时读取，WebUI 修改后无需重启插件 |
| 内存自动回收 | 过期的会话记录会被定期清理，长期运行不会持续占内存 |

## 配置方法

AstrBot WebUI → 插件管理 → 对话频率限制 → 配置

### 1. 全局默认（对所有人/群生效）

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| 私聊限制次数 | 10 | 每个 QQ 号每小时上限；填 0 表示本项不限制 |
| 群聊限制次数 | 30 | 每个群每小时上限（整群共享）；填 0 表示本项不限制 |
| 时间窗口 | 60 分钟 | 滑动窗口长度 |
| 提示后静默秒数 | 60 | 提示发出后，这段时间内该会话不重复提示；填 0 表示每次都提示 |
| 超限提示消息 | 本小时对话次数已用完（{used}/{limit}），最早 {remain} 后可继续聊天~ | 支持占位符 `{used}` `{limit}` `{remain}` |
| 启用私聊限制 | 开 | 总开关 |
| 启用群聊限制 | 开 | 总开关 |

`{remain}` 会格式化为真实剩余时间，例如 `58分10秒`、`9分59秒`、`30秒`。

> 额度填 `0` 按「不限制」处理（沿用 AstrBot 内置限流的语义）。想彻底停掉某一项，请关掉对应的开关。

### 2. 白名单（不受限制）

**用户白名单** — 每行填一个 QQ 号：
```
601514573
123456789
```

**群聊白名单** — 每行填一个群号：
```
601514573
123456789
```

### 3. 单独用户限制（独立额度）

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| 启用单独用户限制 | 开 | 总开关；关闭后下方列表全部不生效，所有用户统一走全局私聊限制 |
| 单独用户限制次数（默认） | 20 | 列表中未单独写次数的用户，统一按此条数限制 |
| 单独限制的用户 | 空 | 列表，见下方填法 |

**单独限制的用户**列表三种填法可混用：

```
123456789                              ← 纯 QQ 号 → 使用上方默认次数（20 条/时）
999:50                                 ← QQ号:次数 → 该用户单独限 50 条/时，覆盖默认
111,222:30                             ← 批量 → 这两个 QQ 都限 30 条/时
```

### 4. 群聊单独限制（独立额度）

每行一条规则，格式：`群号:次数` 或 `群号1,群号2,群号3:次数`

```
601514573:100                        ← 一个群限 100 次/小时
601514573,123456789,111111:80        ← 三个群都限 80 次/小时
```

## 优先级规则

```
消息进来（只有能唤起 LLM 的才算：@机器人 / 引用机器人消息 / 唤醒前缀 / 私聊）
  │
  ├─ QQ号 在用户白名单？        → ✅ 直接放行，不计数
  ├─ 群号 在群聊白名单？        → ✅ 直接放行，不计数
  │
  ├─ 启用单独用户限制 且 QQ号 有单独设置？ → 用该用户的额度
  ├─ 群号 有单独限制？                     → 用该群的额度
  ├─ 都没有单独设置？                      → 用全局默认额度
  ├─ 额度 <= 0？                           → 按未启用处理，放行
  │
  ├─ 还有额度？                 → ✅ 计数 +1，放行给 LLM
  │    └─ 刚好用掉最后一条（且是 @机器人 / 私聊）→ 单独发一条额度用尽提醒
  │
  └─ 额度已用完？
       ├─ @机器人 或私聊
       │    ├─ 静默期内（刚提示过）→ 🔇 不回复，直接拦截
       │    └─ 可以提示           → ❌ 发超限提示（含真实剩余时间），进入静默期，拦截
       └─ 引用 / 唤醒前缀        → 🔇 静默拦截，不回复，LLM 收不到
```

## 常见场景

**场景 1：管理员不受限制**

用户白名单：
```
601514573
```

**场景 2：几个 VIP 用户统一高额度（比如 50 条/时）**

启用单独用户限制：开；单独用户限制次数（默认）：50

单独限制的用户：
```
601514573
123456789
```

**场景 3：某个用户单独收紧/放宽**

单独限制的用户：
```
888888:5        ← 限制得很严
999999:100      ← 给得很宽
```

**场景 4：大群放宽**

群聊单独限制：
```
601514573:100
```

**场景 5：临时关掉某一项限制**

把「私聊限制次数」或「群聊限制次数」填 0，或者直接关掉对应的「启用」开关。

## 执行逻辑说明

- **群里普通聊天不受影响**：不带 @、不引用、不带唤醒前缀的消息根本不会唤醒机器人，也就不进 LLM，插件既不计数也不拦截
- **群聊计数不分唤醒方式**：@机器人、引用机器人消息、唤醒前缀都计入同一个群额度，堵住「不计数却照常消耗 token」的路径
- **超限后按唤醒方式分流**：@机器人 发提示（私聊同理），非 @ 唤醒静默拦截，不在群里刷屏
- 超限后由插件直接拦截，**不会调用 LLM**，不消耗 token
- **滑动窗口**：额度用尽后无需等满一个窗口——窗口内最旧一条记录滑出即恢复一条额度，倒计时提示的就是这个真实时刻
- **额度用尽提醒独立发送**：额度内最后一条消息放行时，提醒作为单独一条消息发出，不与 AI 回复拼接，也不打断正常回复；仅 @机器人 与私聊会发出，非 @ 唤醒用满额度时保持安静
- **静默期**：提示发出后的静默秒数内，该会话的 @机器人 消息不重复提示（非 @ 唤醒本来就不提示）。静默结束仍未解锁则再次提示新的倒计时，已解锁则正常对话。群维度共享额度，故群内静默对整群生效
- **额度 <= 0 表示不限制**：沿用 AstrBot 内置限流的语义
- 所有配置项（含白名单、单独限制、条数、窗口、静默秒数、提示文案）**实时读取，WebUI 修改即时生效**，无需重启
- 计数存于内存：AstrBot 或插件重启后计数清空（不持久化）。注意在 WebUI 每保存一次插件配置，AstrBot 都会热重载插件，同样会清零
- **内存自动回收**：早已过期、再也不会被访问的会话记录会被定期清理，长期运行不会只增不减
- 同一 ID 在单独限制中出现多次，以最后一次为准

---

## 与 AstrBot 内置限流的关系

AstrBot 自带 `RateLimitStage`（设置 → 平台设置 → 频率限制，默认 60 秒 / 30 条，策略 stall 或 discard）。
内置的是「每分钟」的粗粒度保护，按会话生效；本插件是「每小时」的额度控制，带白名单与单独设限。两者叠加生效，排查时注意区分是哪一层拦下的。

## 变更记录

**v1.6.1**
- 修复内存只增不减：早已过期的会话计数与静默记录现在会被自动回收
  （此前「聊过一次就再没出现过」的用户/群，记录会永远留在内存里；实测 2 万个会话过期后一条都不回收）
- 文档补齐：合并此前版本遗漏的功能说明与配置细节

**v1.6.0**
- 群聊不再只统计「@机器人」：引用回复、唤醒前缀等一切能唤起 LLM 的群消息都计入额度
- 超限后按唤醒方式分流：@机器人 才发提示（保留静默保护），非 @ 唤醒静默拦截不回复
- 私聊超限仍照旧发提示
- 修复额度配置为 0 时 `_real_unlock_wait` 对空记录调用 `min()` 抛 ValueError、
  异常被框架吞掉导致限流静默失效的问题；额度 <= 0 沿用 AstrBot 内置语义，按未启用处理

**v1.5.0**
- 新增「启用单独用户限制」总开关，关闭后单独用户限制全部不生效
- 新增「单独用户限制次数（默认）」：列表中纯 QQ 号统一使用该条数
- 列表支持三种填法混用：纯 QQ 号 / `QQ号:次数` / `QQ号1,QQ号2:次数`

**v1.4.0**
- 超限倒计时改为真实解锁时间（窗口内最旧记录滑出的时刻），不再虚报
- 额度用尽（放行最后一条额度）时单独发送一条提醒消息，不与回复拼接
- 新增超限静默期（默认 60 秒，可配置），静默期内消息不回复，防连发刷屏
- 白名单、单独限制改为每次请求实时读取配置，WebUI 修改即时生效
- 群聊默认上限 20 → 30
- 超限提示支持 `{used}` `{limit}` `{remain}` 占位符

**v1.3.0**
- 新增用户白名单、群聊白名单
- 新增用户单独限制、群聊单独限制
- 支持批量格式 `ID1,ID2,ID3:次数`

**v1.2.1**
- 群聊冷却时间基于最后一条消息计算

**v1.2.0**
- 使用 on_llm_request 钩子，不拦截插件指令
