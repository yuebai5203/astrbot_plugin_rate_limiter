# 对话频率限制插件

`astrbot_plugin_rate_limiter` v1.6.0

限制每个用户/群聊在一定时间内的对话次数，超限后不再调用 LLM。支持白名单豁免和按用户/群单独设限。

---

## 功能一览

| 功能 | 说明 |
|------|------|
| 私聊限制 | 每个 QQ 号每小时最多对话 N 次 |
| 群聊限制 | 每个群每小时最多对话 N 次，整群共享额度 |
| 计入范围 | @机器人、引用机器人消息、唤醒前缀 —— 一切能唤起 LLM 的群消息都计数 |
| 超限提示 | @机器人 和私聊会收到提示，含真实剩余等待时间 |
| 静默拦截 | 非 @ 唤醒的消息超限后直接拦截，不回复、不打扰群聊 |
| 时间窗口 | 限制周期可自定义（默认 60 分钟） |
| 静默期 | 提示后 N 秒内不重复回复，防连发刷屏 |
| 用户白名单 | 指定 QQ 号 → 不受任何限制 |
| 群聊白名单 | 指定群号 → 不受任何限制 |
| 单独额度 | 指定 QQ 号 / 群号 → 用独立额度，可批量设置 |

---

## 配置方法

AstrBot WebUI → 插件管理 → 对话频率限制 → 配置

### 1. 全局默认

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| 私聊限制次数 | 10 | 每个 QQ 号每小时上限，填 0 表示不限制 |
| 群聊限制次数 | 30 | 每个群每小时上限（整群共享），填 0 表示不限制 |
| 时间窗口 | 60 分钟 | 滑动窗口长度 |
| 提示后静默秒数 | 60 | 提示发出后这段时间内不再回复，防连发刷屏 |
| 提示消息 | 本小时对话次数已用完… | 支持 `{used}` `{limit}` `{remain}` 占位 |
| 启用私聊限制 | 开 | 关闭后私聊完全不限 |
| 启用群聊限制 | 开 | 关闭后群聊完全不限 |

### 2. 白名单（不受限制）

**用户白名单** — 每行填一个 QQ 号：

```
601514573
123456789
```

**群聊白名单** — 每行填一个群号：

```
601514573
123456789
```

### 3. 单独限制（独立额度）

每行一条规则，格式 `ID:次数` 或 `ID1,ID2,ID3:次数`。

**用户单独限制** — 两种填法：

```
601514573                             ← 只有 QQ 号，用「单独用户默认次数」
601514573:50                          ← 为该用户单独指定 50 次/小时
601514573,123456789,999999:30         ← 三个 QQ 号都限 30 次/小时
```

「单独用户默认次数」（默认 20）是给只写了 QQ 号、没写次数的条目用的。
「启用单独用户限制」总开关关掉后，下面填的单独用户全部不生效，所有私聊统一走全局私聊限制。

**群聊单独限制**：

```
601514573:100                         ← 单个群限 100 次/小时
601514573,123456789,111111:80         ← 三个群都限 80 次/小时
```

## 执行逻辑

```
消息进入 Pipeline
  │
  ├─ WakingCheckStage 判断是否唤醒
  │    ├─ 未唤醒（群里的普通聊天）→ 直接丢弃，不进 LLM，插件也看不到
  │    └─ 已唤醒 → @机器人 / 引用机器人消息 / 唤醒前缀 / 私聊
  │
  ├─ 调用 LLM 前经过本插件
  │    ├─ QQ号 在用户白名单？     → 放行，不计数
  │    ├─ 群号 在群白名单？       → 放行，不计数
  │    ├─ 该用户/群有单独额度？   → 用单独额度，否则用全局默认
  │    ├─ 额度 <= 0？             → 按未启用处理，放行
  │    ├─ 未达上限？              → 计数 +1，放行给 LLM
  │    └─ 已达上限？
  │         ├─ 私聊 或 群里@机器人 → 发提示（受静默期保护），拦截
  │         └─ 非 @ 唤醒           → 静默拦截，不回复
  │
  └─ 被拦截的消息 event.stop_event()，LLM 完全收不到，不消耗 token
```

### 几个要点

- **群聊计数不分唤醒方式**：@机器人、引用机器人消息、唤醒前缀都计入同一个群额度，堵住「不计数却照常烧 token」的路径
- **群里普通聊天不受影响**：不带 @、不引用、不带唤醒前缀的消息根本不会唤醒机器人，也就不进 LLM，插件不管它们
- **只有 @机器人 才会收到超限提示**：引用/前缀这类背景唤醒在超限后静默拦截，避免在群里刷屏
- **私聊超限照常提示**：私聊没有 @ 概念，用户需要知道发生了什么
- **静默期只由提示触发**：非 @ 唤醒用满额度时不会进静默期，免得把之后 @机器人 的提示一并静默掉
- **时间窗口过期后自动恢复**，不需要手动操作
- **插件重启后计数清空**（内存计数，不持久化）
- **同一 ID 在单独限制中出现多次，以最后一次为准**

### 与 AstrBot 内置限流的关系

AstrBot 自带 `RateLimitStage`（设置 → 平台设置 → 频率限制，按会话 60 秒 / 30 条，strategy 为 stall 或 discard）。
内置的是「每分钟」的粗粒度保护，本插件是「每小时」的额度控制，两者叠加生效。

## 常见场景

**场景 1：管理员不受限制**

用户白名单：

```
601514573
```

**场景 2：VIP 用户给高额度**

用户单独限制：

```
601514573:100
```

**场景 3：一批号统一限制**

用户单独限制：

```
601514573,123456789,999999,888888:20
```

**场景 4：大群放宽**

群聊单独限制：

```
601514573:100
```

**场景 5：多个群同一额度**

群聊单独限制：

```
601514573,123456789,111111:80
```

**场景 6：临时关掉某个限制**

把「私聊限制次数」或「群聊限制次数」填 0 即可（额度 <= 0 视为未启用），
或者直接关掉「启用私聊限制 / 启用群聊限制」开关。

## 变更记录

**v1.6.0**

- 群聊不再只统计「@机器人」：引用回复、唤醒前缀等一切能唤起 LLM 的群消息都计入额度
- 超限后按唤醒方式分流：@机器人 才发提示（保留静默保护），非 @ 唤醒静默拦截不回复
- 私聊超限仍照旧发提示
- 修复额度配置为 0 时 `_real_unlock_wait` 对空记录调用 `min()` 抛 ValueError、
  异常被框架吞掉导致限流静默失效的问题

**v1.5.0**

- 新增「启用单独用户限制」总开关
- 单独用户限制支持两种填法：纯 QQ 号（用默认次数）或 `QQ号:次数`（单独指定）

**v1.4.0**

- 超限倒计时改为真实解锁时间，不再虚报
- 额度用尽时单独发送一条提醒消息（不与本次回复拼接）
- 提示后进入静默期（默认 60 秒），期间消息一律不回复，防连发刷屏
- 白名单、单独限制改为每次请求实时读取配置，WebUI 修改即时生效
- 群聊默认上限 20 → 30
- 限制提示支持 `{used}` `{limit}` `{remain}` 占位

**v1.3.0**

- 新增用户白名单、群聊白名单
- 新增用户单独限制、群聊单独限制
- 支持批量格式 `ID1,ID2,ID3:次数`

**v1.2.1**

- 群聊冷却时间基于最后一条消息计算

**v1.2.0**

- 使用 on_llm_request 钩子，不拦截插件指令
